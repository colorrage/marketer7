# Backlog management

Read `../marketer/reference/bootstrap.md` and `data-model.md`. Write only `.marketer/backlog.md`.

## Operations

- **Add:** Capture a concise idea, why it may matter, any evidence/source, and `open` status. Unknown evidence remains `unknown`.
- **List:** Report entries without changing them.
- **Promote:** Mark the backlog item as promoted and reference the newly router-allocated mission or experiment ID. Then invoke the normal mission or experiment planning phase; promotion is not approval or execution.
- **Close:** Retain the item and add a reasoned terminal backlog status such as `declined`, `superseded`, or `tested`.

Do not turn a backlog idea into an experiment with guessed criteria. Return `needs_input` if the user asks to execute an unplanned idea.
